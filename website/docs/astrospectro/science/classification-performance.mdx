## Context and motivation

The conclusion of the PHY-3500 article (Baker, Caillat & Jean, 28 April 2026) uses an **earlier** classifier, run v5 (`ST_100k_xgb_AFGKM_v5`, <RunFact run="20260306T020848Z" path="n.processed" /> spectra processed), whose balanced accuracy on its own test set is <RunFact run="20260306T020848Z" path="metrics.balanced_accuracy" format="pct" />.

The article then projects the predictions of this model onto a different dataset. Its predictions, projected onto the UMAP embedding of the PHY-3500 dataset (**PHY-3500 · G1 · 43,019 spectra**), have a median confidence of <RunFact run="umap_tsne" path="metrics.xgboost_projection.median_confidence" format="pct" /> and follow the geography of the embedding. The article concludes that supervised and unsupervised methods capture the same physical structure, and that projections can serve as qualitative validation spaces for supervised models.

These v5 figures belong to that article and to G1; they are not the metrics of the reference run reported in *Key results*. Run v5 also includes a Gaia-derived column (`M_G`).

## Experimental configuration

### `spectro_only=True` mode

The reference run was trained with `spectro_only=True` in `SpectralClassifier`. The mode is meant to keep only flux-derived features; in addition to the columns that are always excluded (identifiers, `ra`/`dec`, `redshift`, `seeing`, SNR per band, GSP-Phot parameters, parallax, Gaia catalogue magnitudes), it removes every column whose name starts with a non-spectroscopic prefix (`parallax`, `phot_`, `bp_rp`, `teff`, `logg`, …).

The exclusion was prefix-based, and the Gaia-derived columns `M_G`, `M_BP`, `M_RP` and `ag_gspphot` match none of the prefixes: they reached the selected features of the reference run (see the caution above and [Classification](../pipeline/classification.md#feature-columns-and-spectro_only)). The metrics below are therefore those of a mostly — not purely — spectroscopic model. The code has since been fixed with an explicit list of Gaia/photometric columns, but no complete spectro-only reference run exists yet.

### F/G confusion — the trickiest boundary

The main confusion of the reference run is between **F and G**: true F predicted G (<RunFact path="metrics.confusion_matrix.1.2" /> test spectra) and true G predicted F (<RunFact path="metrics.confusion_matrix.2.1" />), and these two classes have the lowest F1 scores (F <RunFact path="metrics.per_class.F.f1" format="num" />, G <RunFact path="metrics.per_class.G.f1" format="num" />). The two types are adjacent in temperature and differ by gradual changes in line strengths; on the PHY-3500 UMAP (G1, model v5), the disputed spectra lie in the transition zone between the two populations. Full analysis: [F/G Confusion Analysis](./fg-confusion.md).

## Geographic coherence in UMAP space

### Principle of supervised/unsupervised cross-validation

This section uses the PHY-3500 dataset (**PHY-3500 · G1 · 43,019 spectra**) and the predictions of run v5, not the reference run. The UMAP projection of XGBoost predictions allows **qualitative validation** of a model: if the supervised classifier has learned the same physical structure as UMAP (unsupervised), predictions should follow the geography of the projection.

## Using the model

### Load and predict

```python
from src.pipeline.classifier import SpectralClassifier

# Load a saved model (<ts> = run identifier)
clf = SpectralClassifier.load_model(
    "data/models/spectral_classifier_xgboost_<ts>.pkl"
)

# Predict on new spectra (same feature format)
predictions = clf.model_pipeline.predict(X_new)
probabilities = clf.model_pipeline.predict_proba(X_new)
```

### Reference run metadata

Each run is documented by:
```
data/models/
├── spectral_classifier_xgboost_<ts>.pkl
└── spectral_classifier_xgboost_<ts>_meta.json
data/reports/<ts>/
└── session_report_xgboost_<ts>.json
```

For the reference run, `<ts>` = <RunFact path="id" format="raw" />. Its meta JSON contains the final hyperparameters, the <RunFact path="features.selected" /> selected features (out of <RunFact path="features.candidates" /> candidates), the class labels and the training file (<RunFact path="trained_on_file" format="raw" />); the session report records the model MD5 hash (<RunFact path="md5" format="raw" />).
