# 🎨 Page Style Guide & Master Templates

This is the **single source of truth** for how every page in `research-docs` should be structured, written, and formatted. Before writing any new page, read the section that applies to your page type.

:::info Internal reference
This guide is for you — future Alex — not for external readers. It documents the UX patterns of your best existing pages (Autoencoder, PCA, UMAP, Dimred index) so every future page matches their level.
:::

---

## 1. The 5 ingredients every page shares

Regardless of page type, every page must have these 5 things:

| # | Ingredient | What it looks like |
|---|---|---|
| **1** | Opening sentence | What this page covers + dataset context |
| **2** | Key results block | 4–6 stat cards — always first substantive section |
| **3** | Admonition for context | `:::note` with paper/run reference or important caveat |
| **4** | At least one table | Comparison table, data table, or parameter table |
| **5** | Cross-references footer | Links to related pages |

## 2. Page types and their templates

### 2.1 Method / Analysis page
*Used for: PCA, UMAP, Autoencoder, t-SNE, SHAP, Classification, Dimred methods*

```
Frontmatter
Opening paragraph (2–3 sentences)
Contextual admonition (paper ref or run ID)
---
## Key results        ← ALWAYS FIRST
[stats cards]
---
## Why [this method]? ← comparative table vs alternatives
---
## [Theory/Architecture]
[math or diagram]
[code block]
---
## [Results sections]
[figures + tables]
[interpretations]
---
## Reference figures  ← gallery of all figures
## Implementation     ← code snippet + module path
## Cross-references   ← links
```

**Opening paragraph formula:**
> *"This page documents [what] applied to the [N spectra · X features] of [dataset]. [Method] is [role in project]. [One sentence positioning it vs the other methods studied]."*

## 3. The stat card block

The stat card block at the top of every page is your most important UX pattern. Here is the exact MDX syntax:

```mdx
## Key results

<div className="stats-row">

**0.489**
Reconstruction MSE
autoencoder z = 2 · N = 43,019

**z=2 ≈ PCA@10**
Compression equivalence
MSE(AE, z=2) ≈ MSE(PCA, k=10)

**145**
Training epochs
Best val loss = 0.548 · Early stopping

**107×**
QSO vs star error
MSE(QSO)/MSE(STAR) — anomaly detection

</div>
```

**Rules for stat cards:**
- Always 4–6 cards, never more
- First line: the number (bold, large)
- Second line: the metric name
- Third line: context in small text (dataset, condition, comparison)
- Include the run ID or N count somewhere in this block

## 4. Admonition patterns

Use these exact patterns consistently:

```mdx
:::info Run context
**Experiment:** `ST_350k_xgb_AFGKM_v6` · **Saved:** `20260522T161236Z` · **N:** 349,998 spectra
:::

:::note PHY-3500 reference
This analysis is mentioned in Baker, Caillat & Jean (28 April 2026) but the detailed results
are only on this page. See the article for the summary.
:::

:::warning Limitation
[State a known limitation clearly here — never hide limitations in footnotes]
:::

:::tip Key finding
[A bold, specific, quantified scientific finding — use sparingly, max 1–2 per page]
:::

:::danger Do not
[For pipeline pages: what NOT to do, common mistakes]
:::
```

## 5. Table conventions

### Comparison table (method vs method)
Always use this format for comparing methods:

```mdx
| Property | PCA | UMAP | t-SNE | AE |
|---|---|---|---|---|
| Linear? | ✓ | ✗ | ✗ | ✗ |
| Parametric? | ✓ | Partial | ✗ | ✓ |
| Interpretable axes | ✓ | ✗ | ✗ | Partial |
| Stability | Exact | Low | ~60× better | Moderate |
| CPU time | <1 s | 40 s | 80 s | 144 s |
```

### Parameter table (hyperparameters)
```mdx
| Parameter | Value | Why |
|---|---|---|
| `n_neighbors` | 15 | Best local/global trade-off (sensitivity test) |
| `min_dist` | 0.1 | Compact but not over-compressed |
| `random_state` | 42 | Reproducibility |
```

### Hyperparameter sensitivity table (the styled version)

```mdx
| Value | Behaviour | Status |
|---|---|---|
| 5 | Fragmentation · global structure lost | ✗ Avoid |
| **15** | **Best local/global trade-off** | **✓ Retained** |
| 30 | Robust structure · slight coalescence | ⊙ Robust |
| 50 | Qualitative structure preserved | ⊙ Robust |
| 100 | Cluster coalescence · loss of detail | ✗ Avoid |
```

## 6. Tabs pattern

Use tabs when comparing two variants of the same thing (UMAP vs t-SNE, before vs after, v5 vs v6):

```mdx
import Tabs from '@theme/Tabs';
import TabItem from '@theme/TabItem';

<Tabs>
  <TabItem value="umap" label="UMAP — n_neighbors" default>

| n_neighbors | Behaviour | Status |
|---|---|---|
| 5 | Fragmentation | ✗ Avoid |
| **15** | Best trade-off | ✓ Retained |

  </TabItem>
  <TabItem value="tsne" label="t-SNE — Perplexity">

| Perplexity | Behaviour | Status |
|---|---|---|
| 15 | Transition | △ Transition |
| **30** | Best trade-off | ✓ Retained |

  </TabItem>
</Tabs>
```

## 8. Figure conventions

Every figure should have:
1. A caption sentence (not just a filename)
2. Physical interpretation of what you see
3. An alt text for accessibility

```mdx
![PCA explained variance curve showing elbow at k=10 components with 75% cumulative variance](../../../figures/pca_variance_explained.png)

*Figure 1 — PCA explained variance. The first 10 components capture 75% of the total variance. The elbow at k=5 marks the boundary between principal axes with clear physical meaning and noise-dominated axes.*
```

## 11. Writing style rules

### Sentence structure
- **First paragraph:** always past tense for "this page presents" + present tense for the result
- **Section headers:** `##` for major sections, `###` for subsections — **never** `####`
- **No bullet lists for analysis** — use tables instead; bullets are only for quick-reference lists

### Numbers and quantities
Always include units:
- `N = 43,019 spectra` (not just 43019)
- `MSE = 0.489` (not just 0.489)
- `ρ(Teff) = +0.831` (not just 0.831, always include sign)
- `Ryzen 9 5950X · 32 threads` for hardware context

### Dataset context
Every method/analysis page must state the dataset at least once in the first paragraph:
> *"...applied to the **183 spectroscopic features** of N = 43,019 LAMOST DR5 × Gaia DR3 spectra."*

As of run v6, update to: **99 selected features** of **N = 349,998 spectra**.

### Physical interpretations
- Never state a result without its physical meaning
- Always link back to astrophysics: *"This confirms that [feature] traces [physical property], consistent with [reference]"*
- Use the hedge: *"This suggests..."* vs *"This confirms..."* based on evidence level (see Claims Register)

### Cross-references format
End every page with a standardized cross-references section:

```mdx
---

## Cross-references

| Related page | Relation |
|---|---|
| [PCA — physical interpretation](./pca) | Linear baseline for comparison |
| [UMAP & HDBSCAN](./umap-hdbscan) | Non-parametric complement |
| [Comparison — PCA vs UMAP vs AE](./comparison) | Synthesis across all methods |
| [Feature Catalogue](../data/feature-catalog) | Definition of the 183 features used |
| [Scientific Claims Register](../../atlas/claims-register) | Evidence level for findings on this page |
```

## 13. Page-type checklist

Before publishing any page, verify:

**All pages:**
- [ ] Frontmatter has `title` and `description` (with dataset context)
- [ ] Opening paragraph states what the page covers in ≤3 sentences
- [ ] At least one `---` divider after intro
- [ ] Key results section is present and first
- [ ] No `????` or `TBD` visible to readers
- [ ] All figures have captions
- [ ] Cross-references section at bottom

**Method pages additionally:**
- [ ] Comparison table vs other methods
- [ ] Physical interpretation of results
- [ ] Code block with module path in comment

**Data pages additionally:**
- [ ] Schema table (column → type → description)
- [ ] How to load code block

**Guide pages additionally:**
- [ ] Prerequisites listed in `:::note`
- [ ] Each step has a code block
- [ ] Expected output described
